3.1 Επισκόπηση Συστήματος

Το σύστημα ETL είναι μια πλατφόρμα επεξεργασίας δεδομένων σε πραγματικό χρόνο με αρχιτεκτονική microservices. Αποτελείται από τρία ανεξάρτητα components: το ETL API για υποβολή configurations, τον File Producer για παραγωγή δεδομένων αισθητήρων, και το Flink Job για επεξεργασία ροών. Τα components επικοινωνούν αποκλειστικά μέσω Apache Kafka, ενώ τα αποτελέσματα αποθηκεύονται σε MongoDB.

Το Σχήμα 3.1 παρουσιάζει την αρχιτεκτονική υψηλού επιπέδου. Τα Kafka topics etl.config.v1 και etl.input.v1 τροφοδοτούν το Flink Job, το οποίο εκπέμπει αποτελέσματα στο etl.output.v1.

3.2.1 ETL API Service

Το ETL API είναι ένα REST API υλοποιημένο με Spring Boot. Αποτελεί το σημείο εισόδου του συστήματος για τους χρήστες. Δέχεται configurations σε JSON μορφή μέσω HTTP POST στο endpoint /config. Κάθε configuration περιέχει ένα μοναδικό jobId και μια λίστα μετασχηματισμών προς εφαρμογή.

Η υπηρεσία εκτελεί επικύρωση του configuration: ελέγχει ότι υπάρχει το jobId, ότι οι τύποι μετασχηματισμών είναι έγκυροι, και ότι τα απαραίτητα params υπάρχουν για κάθε τύπο. Μετά την επικύρωση, το configuration σειριοποιείται σε JSON και δημοσιεύεται στο Kafka topic etl.config.v1. Η υπηρεσία διατηρεί επίσης ένα in-memory registry των υποβληθέντων jobs για παρακολούθηση κατάστασης.

Endpoint Method Περιγραφή
/config POST Υποβολή configuration - επικύρωση και δημοσίευση στο Kafka
/status/{jobId} GET Κατάσταση εργασίας από το job registry
/health GET Health check για container orchestration
/jobs GET Λίστα όλων των καταχωρημένων εργασιών

3.2.2 File Producer Service

Η υπηρεσία File Producer παράγει δεδομένα αισθητήρων και τα δημοσιεύει στο Kafka topic etl.input.v1. Υποστηρίζει δύο modes λειτουργίας:

  • File mode: Διαβάζει προκαθορισμένα δεδομένα από JSON αρχείο. Χρήσιμο για reproducible tests και demos.
  • Random mode: Δημιουργεί δεδομένα αισθητήρων με ρεαλιστικές τιμές βασισμένες σε κατανομή Gauss. Κάθε εγγραφή περιλαμβάνει: τύπο αισθητήρα, τιμή μέτρησης, μονάδα μέτρησης, timestamp, τοποθεσία, και δείκτη ποιότητας.

Στον random mode, η υπηρεσία προσομοιώνει 6 τύπους αισθητήρων σε 8 τοποθεσίες, παράγοντας 48 μηνύματα ανά κύκλο. Η παραγωγή τιμών ακολουθεί κανονική κατανομή (Gaussian distribution) με κεντρική τιμή (mean) και τυπική απόκλιση (σ) ανά τύπο αισθητήρα, εξασφαλίζοντας ρεαλιστική διασπορά τιμών. Ο ρυθμός παραγωγής είναι παραμετροποιήσιμος μέσω environment variable.

Τύπος Αισθητήρα Μονάδα Εύρος Τιμών Κατανομή
temperature Celsius -30 έως 70 Gaussian(μ=22, σ=8)
pressure hPa 950 - 1080 Gaussian(μ=1013, σ=15)
humidity percent 20 - 90 Gaussian(μ=50, σ=15)
air_quality AQI 0 - 200 Gaussian(μ=50, σ=25)
light lux 50 - 1000 Gaussian(μ=350, σ=100)
noise dB 30 - 80 Gaussian(μ=45, σ=10)

Πίνακας 3.2: Τύποι αισθητήρων, εύρη τιμών και κατανομές

Οι τιμές περιορίζονται (clamped) στα καθορισμένα όρια για να αποφευχθούν ακραίες τιμές από την ουρά της κανονικής κατανομής. Ο δείκτης ποιότητας (data_quality) υπολογίζεται με βάση την απόκλιση από την τυπική τιμή κάθε αισθητήρα και λαμβάνει τιμές: excellent, good, fair, ή poor.

Τοποθεσίες: room-a, room-b, room-c, room-d, lobby, conference-room, kitchen, server-room

3.2.3 Flink Job

Το Flink Job είναι ο πυρήνας επεξεργασίας του συστήματος. Καταναλώνει δύο ροές δεδομένων από το Kafka: configurations από το etl.config.v1 και sensor events από το etl.input.v1. Η βασική πρόκληση είναι η συνένωση αυτών των δύο ροών: κάθε sensor event πρέπει να επεξεργαστεί με βάση τα ενεργά configurations.

Για την επίλυση αυτής της πρόκλησης χρησιμοποιείται ο CoFlatMap operator του Flink. Ο operator αυτός δέχεται δύο εισόδους και διατηρεί εσωτερική κατάσταση (state). Όταν φτάνει ένα configuration, αποθηκεύεται στο state. Όταν φτάνει ένα sensor event, ανακτώνται τα configurations από το state και εφαρμόζονται οι αντίστοιχοι μετασχηματισμοί. Αυτή η αρχιτεκτονική επιτρέπει δυναμική αλλαγή των μετασχηματισμών χωρίς επανεκκίνηση του job.

Τα αποτελέσματα της επεξεργασίας δημοσιεύονται στο Kafka topic etl.output.v1 και αποθηκεύονται στη MongoDB για μόνιμη αποθήκευση.

3.3 CoFlatMap: Ο Βασικός Operator

Το CoFlatMap pattern είναι η καρδιά της αρχιτεκτονικής επεξεργασίας. Επιτρέπει τη συνένωση δύο ετερογενών ροών (configurations και sensor events) σε έναν operator με κοινή κατάσταση.

3.3.1 Λειτουργία

Ο CoFlatMap processor υλοποιεί την διεπαφή CoFlatMapFunction<EtlConfig, SensorEvent, EtlResult> του Flink. Διαθέτει δύο μεθόδους:

  • flatMap1(EtlConfig config): Καλείται όταν φτάνει ένα configuration. Το configuration αποθηκεύεται στο MapState<String, EtlConfig> με κλειδί το jobId. Εκπέμπεται ένα confirmation result.
  • flatMap2(SensorEvent event): Καλείται όταν φτάνει ένα sensor event. Επαναλαμβάνει όλα τα αποθηκευμένα configurations και για καθένα εφαρμόζει τους μετασχηματισμούς στο event. Εκπέμπει ένα ή περισσότερα results.

Η χρήση keyed state εξασφαλίζει ότι τα configurations και events με το ίδιο key επεξεργάζονται από τον ίδιο parallel task, διατηρώντας τη συνέπεια.

3.3.2 Εφαρμογή Μετασχηματισμών

Όταν φτάνει ένα sensor event, η μέθοδος flatMap2 εκτελεί τα εξής βήματα:

  1. Ανάκτηση όλων των configurations από το state
  2. Για κάθε configuration:
    • Έλεγχος αν το event αφορά τον sensor που ορίζει το configuration
    • Εφαρμογή των element transformations διαδοχικά (filter, normalize, text ops)
    • Αν η εγγραφή περάσει τα φίλτρα, προετοιμασία για aggregation ή άμεση εκπομπή
  3. Εκπομπή του/των EtlResult

Τα element transformations εφαρμόζονται εντός του CoFlatMap. Τα aggregation transformations (sum, max, min, avg) απαιτούν windowing και εκτελούνται σε επόμενο στάδιο του pipeline.

3.3.3 Διαχωρισμός Ροής

Μετά τον CoFlatMap, η ροή διαχωρίζεται με βάση το πεδίο aggregationType του EtlResult:

  • Results χωρίς aggregation: Προωθούνται απευθείας στους sinks (Kafka, MongoDB)
  • Results με aggregation: Περνούν από keyBy → Window → Aggregate πριν τους sinks

3.4 Processing Pipeline

Η πλήρης ροή επεξεργασίας του Flink Job απεικονίζεται στο Σχήμα 3.4. Τα στάδια είναι:

  1. Kafka Consumer: Κατανάλωση μηνυμάτων από τα topics config και input
  2. Filter null: Αφαίρεση null records (malformed JSON)
  3. CoFlatMap: Συνένωση streams και εφαρμογή element transformations
  4. Split: Διαχωρισμός σε aggregation και non-aggregation results
  5. KeyBy + Window + Aggregate: Για aggregation results μόνο
  6. Union: Ένωση των δύο κλάδων
  7. Sinks: Kafka sink και MongoDB sink

Σχήμα 3.4: Flink processing pipeline

3.4.1 Windowing και Aggregation

Για τα results που απαιτούν aggregation, χρησιμοποιούνται Tumbling Processing Time Windows διάρκειας 10 δευτερολέπτων. Τα Tumbling windows είναι μη επικαλυπτόμενα: κάθε event ανήκει σε ακριβώς ένα παράθυρο.

Το grouping γίνεται με composite key: groupingKey + jobId + aggregationType. Αυτό εξασφαλίζει ότι τα aggregations υπολογίζονται ξεχωριστά για κάθε συνδυασμό location/sensor, job, και τύπο aggregation.

Ο Aggregate operator υλοποιεί custom AggregateFunction που υποστηρίζει sum, max, min, και avg. Για το avg διατηρείται sum και count στον accumulator.

3.5 Μετασχηματισμοί (Transformations)

Το σύστημα υποστηρίζει δύο κατηγορίες μετασχηματισμών:

3.5.1 Element Transformations

Εφαρμόζονται διαδοχικά σε κάθε εγγραφή μέσα στον CoFlatMap operator. Η σειρά εφαρμογής καθορίζεται από τη σειρά εμφάνισης στο configuration. Αν ένα φίλτρο απορρίψει την εγγραφή, η επεξεργασία σταματά για αυτό το configuration.

Τύπος Περιγραφή Παράμετροι
filter_greater Διατηρεί εγγραφές όπου field > threshold sensor, field, threshold
filter_less Διατηρεί εγγραφές όπου field < threshold sensor, field, threshold
normalize Κανονικοποίηση: (value - min) / (max - min) field, min, max
to_lowercase Μετατροπή string πεδίου σε πεζά field
to_uppercase Μετατροπή string πεδίου σε κεφαλαία field
trim_whitespace Αφαίρεση whitespace από αρχή/τέλος field

3.5.2 Aggregation Transformations

Εφαρμόζονται σε ομάδες εγγραφών εντός του χρονικού παραθύρου (10 sec). Απαιτούν την παράμετρο keyBy στο configuration για να καθοριστεί το πεδίο ομαδοποίησης (π.χ. location, sensor).

max Μέγιστη τιμή του πεδίου field, sensor (προαιρετικό)
min Ελάχιστη τιμή του πεδίου field, sensor (προαιρετικό)
avg Μέσος όρος τιμών του πεδίου field, sensor (προαιρετικό)

Η υποδομή βασίζεται σε Docker containers. Το Docker Compose ορίζει τις υπηρεσίες και τις εξαρτήσεις τους. Η στοίβα οργανώνεται σε δύο επίπεδα:

  • Infrastructure Layer: Zookeeper, Kafka, MongoDB - οι υπηρεσίες υποστήριξης
  • Application Layer: ETL API, File Producer, Flink - τα microservices της εφαρμογής

3.9 Ροή Δεδομένων End-to-End

Η πλήρης ροή δεδομένων από την υποβολή configuration έως την αποθήκευση αποτελεσμάτων:

  1. Config Submission: Ο χρήστης στέλνει POST στο /config με JSON configuration. Το ETL API επικυρώνει και δημοσιεύει στο etl.config.v1.
  2. Data Generation: Ο Producer δημιουργεί sensor events και τα δημοσιεύει στο etl.input.v1 με configurable rate.
  3. Stream Processing: Το Flink Job καταναλώνει και τα δύο streams. Ο CoFlatMap αποθηκεύει τα configs στο state και επεξεργάζεται τα events. Τα aggregations περνούν από windowing.
  4. Result Storage: Τα αποτελέσματα δημοσιεύονται στο etl.output.v1 και αποθηκεύονται στη MongoDB.
