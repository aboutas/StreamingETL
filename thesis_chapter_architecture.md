# Κεφάλαιο: Αρχιτεκτονική και Σχεδίαση

## 1. Επισκόπηση Συστήματος

Το σύστημα ETL (Extract, Transform, Load) είναι μια πλατφόρμα επεξεργασίας δεδομένων σε πραγματικό χρόνο, σχεδιασμένη με αρχιτεκτονική microservices. Επεξεργάζεται ροές δεδομένων από αισθητήρες, εφαρμόζει δυναμικά διαμορφώσιμους μετασχηματισμούς, και παράγει συγκεντρωτικά αποτελέσματα.

### 2.2 ETL API Service

Το ETL API είναι ένα REST API βασισμένο σε Spring Boot που δέχεται configurations για ETL εργασίες.

**Αρμοδιότητες:**
- Λήψη και επικύρωση configurations μέσω REST endpoint
- Δημοσίευση configurations στο Kafka topic `etl.config.v1`
- Παρακολούθηση κατάστασης εργασιών (Job Registry)

**REST Endpoints:**
| Endpoint | Method | Περιγραφή |
|----------|--------|-----------|
| `/config` | POST | Υποβολή νέου configuration |
| `/status/{jobId}` | GET | Κατάσταση εργασίας |
| `/health` | GET | Health check |
| `/jobs` | GET | Λίστα όλων των εργασιών |

### 2.3 File Producer Service

Υπηρεσία παραγωγής δεδομένων αισθητήρων με δύο modes λειτουργίας.

**Modes Λειτουργίας:**
| Mode | Περιγραφή |
|------|-----------|
| `file` | Ανάγνωση δεδομένων από JSON αρχείο |
| `random` | Δημιουργία ρεαλιστικών δεδομένων αισθητήρων |

**Τύποι Αισθητήρων:**
- temperature (Celsius)
- pressure (hPa)
- humidity (percent)
- air_quality (AQI)
- light (lux)
- noise (dB)

**Τοποθεσίες:**
- room-a, room-b, room-c, room-d
- lobby, conference-room, kitchen, server-room

### 2.4 Flink Job

Η κεντρική μονάδα επεξεργασίας ροών δεδομένων, υλοποιημένη με Apache Flink.

## 4. Apache Flink - Αρχιτεκτονική Επεξεργασίας

### 4.1 CoFlatMap Pattern

Το σύστημα χρησιμοποιεί το CoFlatMap pattern του Flink για τη συνένωση δύο ροών δεδομένων: configurations και sensor events.

│                       CoFlatMap PROCESSING PATTERN                       │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Config Stream                          Event Stream                   │
│   (etl.config.v1)                       (etl.input.v1)                 │
│        │                                      │                         │
│        ▼                                      ▼                         │
│   ┌─────────┐                            ┌─────────┐                    │
│   │ keyBy   │                            │ keyBy   │                    │
│   │ (jobId) │                            │(sensor) │                    │
│   └────┬────┘                            └────┬────┘                    │
│        │                                      │                         │
│        └──────────────┬───────────────────────┘                         │
│                       │                                                 │
│                       ▼                                                 │
│              ┌─────────────────┐                                        │
│              │  CoFlatMap      │                                        │
│              │  Processor      │                                        │
│              │                 │                                        │
│              │ ┌─────────────┐ │                                        │
│              │ │ Config State│ │  MapState<jobId, EtlConfig>           │
│              │ │  (keyed)    │ │                                        │
│              │ └─────────────┘ │                                        │
│              │                 │                                        │

## 9. Σχεδιαστικές Αποφάσεις

### 9.1 Γιατί CoFlatMap;

| Πλεονέκτημα | Περιγραφή |
|-------------|-----------|
| Stateful Processing | Αποθήκευση configurations σε Flink state |
| Dynamic Configuration | Αλλαγή μετασχηματισμών χωρίς restart |
| Single Pipeline | Μία ενοποιημένη ροή επεξεργασίας |
| True Parallelism | Κατανομή φορτίου σε πολλαπλά tasks |

### 9.2 Γιατί Processing Time Windows;

| Πλεονέκτημα | Περιγραφή |
|-------------|-----------|
| Simplicity | Δεν απαιτούνται watermarks |
| Low Latency | Άμεση επεξεργασία χωρίς αναμονή |
| Predictability | Σταθερά παράθυρα βάσει wall clock |

### 9.3 Γιατί Kafka;

| Πλεονέκτημα | Περιγραφή |
|-------------|-----------|
| Decoupling | Αποσύνδεση producers από consumers |
| Durability | Persistent storage για replay |
| Scalability | Horizontal scaling με partitions |
| Ecosystem | Native Flink integration |
